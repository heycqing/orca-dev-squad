# 提交整理助手

把每个提交整理成审核者能独立理解的一个功能。适用于用户指定的任何 Git 仓库；多个仓库同时存在时，先确定目标仓库。

## 检查范围

- 查看工作区、暂存区、分支和相关提交范围。区分未提交改动与已有提交。
- 阅读目标仓库的 AGENTS.md 和 Git hook。仓库根目录有 `.codegraph/` 时，先用 CodeGraph 理解代码关系。
- 分析代码差异及判断功能依赖所需的少量上下文。不靠无关文档推断功能。
- 保留用户现有改动。未经授权，不删除文件、不重置改动、不改写已发布历史、不推送、不创建 PR。

## 选择文件

默认只选业务代码。只有选定功能缺少清单、迁移、结构定义、构建配置或运行资源就无法工作时，才将它们纳入提交，并说明依赖关系。

单元测试可选。直接覆盖该功能且有助于审核或防止回归的测试，放在同一功能提交内。

排除文档、笔记、计划、报告、截图、日志、缓存、生成产物、临时文件及无关格式改动。不要使用 `git add .`、`git add -A` 或宽泛的目录暂存；按精确路径或代码块暂存。排除提交不等于删除文件。

根据路径、文件名、内容哈希和代码实现检查重复或重叠文件。报告两端路径及重复依据，保留真正需要的实现，不自动删除。

## 功能边界

一个提交只表达一个可独立理解的功能或内聚的内部能力。根据调用链、导入和行为关联跨文件改动。同一文件包含无关功能时，按代码块拆分。

仅当两个功能无法独立构建、运行或审核时才合并，并说明依赖。不要把剩余代码随意塞进一个 `chore` 提交。

对于已有提交，先给出拆分、合并、调整顺序或补丁提交的映射。只因提交信息不完美，不改写历史。改写前检查是否已推送或共享，并保留无关改动。

## 执行与报告

1. 记录 `git status --porcelain=v1`、当前分支、上游分支和相关差异；标记原本已暂存的改动。
2. 给出简明方案：每个拟议提交的功能与精确文件或代码块、排除项、疑似重复文件、必须纳入的非代码依赖。无法确定的分组请用户判断。
3. 当请求包含创建提交时，逐组暂存；提交前检查 `git diff --cached --name-status`、`git diff --cached --check` 和完整暂存差异。使用准确描述该功能的提交信息。
4. 提交前检查 hook。若 hook 会暂存计划外文件，阻止其混入本次提交，并单独运行相关校验。提交后用 `git show --format=fuller --name-status HEAD` 核对实际文件清单。校验失败不得隐瞒或绕过。
5. 报告提交哈希及功能、留在工作区的排除文件、重复发现、已运行的检查和待决定事项。排除文件仍在时，不宣称工作区干净。

只请求审核时，在第 2 步结束。请求新建提交时，不擅自改写旧提交。请求整理提交序列时可以重组本地序列；改写已推送或共享的历史前必须明确确认。
